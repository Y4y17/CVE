### Vulnerability Location: /DocSystem/Doc/uploadDoc.do
### Affected Range: DocSys V2.02.80
### Vulnerability Cause: The uploadDoc.do contains a serious vulnerability that enables attackers to upload arbitrary files.
### Vulnerability Impact: Obtaining server access privileges.
### Link: https://github.com/RainyGao-GitHub/DocSys


### 漏洞描述
用户通过认证后，攻击者可以上传任意文件到服务器，导致服务器被用户接管。

### 漏洞证明

这个漏洞是后台的，而且需要是管理员权限，在/uploadDoc.do 接口中：

<img width="782" height="620" alt="Image" src="https://github.com/user-attachments/assets/85cafac8-2a92-4c73-a51d-017a1c64d23f" />

如果传递的 usage 不为空的话，就会判断当前的用户是否具备管理员的权限。后续就不会存在任何的文件校验，且文件名是用户自己可以控制的！

<img width="1411" height="188" alt="Image" src="https://github.com/user-attachments/assets/4bb9fd96-6e99-47db-9181-8c4f2db8a6a8" />

这里我们要分析的是，能否无需管理员权限，或者无需登录就可以直接上传！

<img width="839" height="622" alt="Image" src="https://github.com/user-attachments/assets/bdd68aee-608f-4231-8aab-96838f7d9689" />

继续往下分析，如果 usage 为空，就不会进入到 if 条件中！

1. 调用常规权限校验 `checkAndGetAccessInfoEx`

2. 允许普通用户或分享外链用户（要有对应的读写权限）

3. 执行`saveDocToRepos`

<img width="1152" height="609" alt="Image" src="https://github.com/user-attachments/assets/34c03dd3-403c-48b0-b081-213940b6a212" />

因为没有传递 shareId，就会验证是不是登录！

<img width="1322" height="532" alt="Image" src="https://github.com/user-attachments/assets/486c587c-4713-4525-b0b1-a24e59ebfb0e" />
